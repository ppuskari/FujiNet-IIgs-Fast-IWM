# P0.2B — first private Fast-IWM wire experiment

## Why this experiment exists

The stock 2.8 MHz ROM 3 IIgs has already established two useful transport baselines against the same FujiNet hardware:

- GS/OS `DRead`, standard SmartPort: ~16.4 KB/s / ~131 kbit/s.
- Direct standard SmartPort `READBLOCK $01`: ~22.6 KB/s / ~180.8 kbit/s.

The direct standard path barely clears the 22.05 kHz mono 8-bit PCM requirement of 22,050 B/s / 176.4 kbit/s, but does not provide enough practical headroom for a background streaming service.

IWMPROBE P0.2A through P0.2A5 established that the IIgs returns to an idle IWM mode value of `$0C` (bit 3 set), but attempts to change the low mode bits from application code were rejected even with immediate readback and with `$C031` bit 6 (`35DISK`) asserted. P0.2B therefore stops trying to modify the IWM mode register.

## Design rule

P0.2B does **not** modify ordinary SmartPort timing.

Normal FujiNet SmartPort remains exactly as upstream implements it:

- normal SmartPort transmit SPI handle: 1 MHz;
- normal command/packet framing unchanged;
- normal ROM/GS/OS mounting and booting unchanged.

A second SPI transmit device is created only when firmware is compiled with:

```text
-D IIGS_FAST_IWM_PROBE
```

That private handle runs at 2 MHz. FujiNet's existing `encode_spi_packet()` represents every logical IWM bit with two SPI bits. Reusing the same encoded waveform at twice the SPI clock halves the nominal IWM cell from 4 us to 2 us without changing ordinary SmartPort.

## Private phase protocol

This is intentionally **not SmartPort protocol** yet. It is a wire-rate experiment.

The IIgs uses a phase pattern that normal FujiNet SmartPort does not treat as an enable state:

```text
PH3 PH2 PH1 PH0
 1   1   1   0     arm private responder
```

FujiNet then asserts ACK low through its existing `SP_ACK` / WRPROT line.

The IIgs raises PH0:

```text
PH3 PH2 PH1 PH0
 1   1   1   1     request one private fast packet
```

FujiNet transmits the test packet with the private 2 MHz SPI handle.

After each packet the IIgs drops PH0 back to `1110`, which arms the next packet.

On exit the IIgs pulses the ordinary SmartPort reset signature `0101` and then leaves all phase lines low.

## Wire packet

Each P0.2B probe packet contains:

```text
16 x $FF                  sync
$D5 $AA $96               marker
512 deterministic bytes   $80 | (index & $7F)
4 x $FF                   guard
```

All payload bytes have bit 7 set so the IIgs can consume them through the IWM read-data latch using a tight polling loop.

The first packet is pattern-verified. If it passes, FASTPROBE reads 256 packets (128 KiB logical payload) and reports elapsed 60 Hz ticks, bytes/sec, and kbit/sec.

## Why 512 bytes first

The final streamer wants exact 16 KiB producer quanta. A natural later burst is 32 x 512 bytes = 16,384 bytes. P0.2B deliberately proves the physical 2 us receive path first before adding sequential burst semantics or streamer integration.

## Expected outcomes

P0.2B may fail in useful ways:

- `ACK timeout`: the private phase/ACK route needs adjustment.
- `byte timeout`: the IWM is not latching the 2 us stream the way expected.
- `pattern mismatch`: timing is close enough to receive bytes but not yet reliable.
- `PASS`: proceed to sustained measurement, then P0.2C reduced-overhead 16 KiB burst.

## Firmware target caution

The patch is written against pinned upstream FujiNet firmware commit:

```text
b0a9483463c93ab61279d265467159c0d27c9f82
```

CI may compile the patch against upstream `fujiapple-rev0` solely as a source/build validation target. Do **not** flash that build merely because CI succeeds. Before hardware flashing, confirm the actual FujiApple board/build configuration in use, including any `MASTERIES_*`, `NO3STATE`, or other board-specific flags.
