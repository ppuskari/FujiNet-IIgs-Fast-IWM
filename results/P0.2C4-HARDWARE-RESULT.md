# P0.2C4 hardware result

Observed serial sequence:

```text
FASTIWM C3 READ ... block=7fa55a raw=5a a5 7f armed=0 grace=0
FASTIWM ARM block=7fa55a count=1 raw=5a a5 7f
FASTIWM C4 AUTOSEND scheduled due=114570 now=114520
FASTIWM C4 AUTO TX START count=1 now=114570
```

No `FASTIWM C4 AUTO TX DONE` followed.

Conclusion: SmartPort arm negotiation and delayed scheduling are proven. The remaining failure occurs inside `iwm_send_fast_probe_spi()` before it returns to service context.
