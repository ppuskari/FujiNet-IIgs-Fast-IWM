# P0.2C8 — enforce 8-bit IWM mode-register assembly

P0.2C7 confirmed that the normal SmartPort arm READBLOCK reached FujiNet and
that P0.2C4 transmitted its delayed 512-byte packet successfully: the transmit
started 50 ms after the arm and completed in 9 ms with `err=0`.

The IIgs entered the monitor at `$0A/0640` before the receive loop. Its status
register was `$24`, so the accumulator was 8-bit. The P0.2C7 symbol/listing map
showed `AND #IWMModeMask` assembled at `$063E` as `29 1F 00`. The CPU consumed
the 8-bit immediate `29 1F`, then executed the remaining `$00` byte at `$0640`
as `BRK $00`.

P0.2C8 changes one host-side variable only:

1. Keep FujiNet P0.2C4 delayed-autosend firmware unchanged.
2. Retain all P0.2C7 IWM mode, receive, reset, and restore behavior.
3. Execute `SEP #$20` at `SetIWMModeC` entry so the runtime and Merlin
   assembler state both use an 8-bit accumulator.
4. Require the assembled mode-mask instruction to be exactly `29 1F`.

Acceptance criterion: `FAST PASS: exact 512-byte 2us payload verified.`

If P0.2C8 times out rather than passing, that will be the first valid hardware
result for the IWM `$0F` 2-us receive experiment.
