# P0.2C7 — program the IIgs IWM for 2 us receive

P0.2C4 proved FujiNet recognizes the magic arm READBLOCK `$7FA55A`, schedules the private transmit, and completes the 512-byte 2 MHz/2 us-cell packet with `err=0`. The observed wire transmit lasts about 9 ms.

P0.2C5 corrected the IIgs Read Data register selection by asserting DRIVE ENABLE and protecting the Slot-6 automatic slowdown bit. P0.2C6 removed post-arm TextTools latency and the obsolete manual `1010 -> 1011` trigger, but neither build changed the IWM bit-cell mode itself.

Apple's IIgs 3.5-inch IWM programming documentation defines mode bit `C` as the bit-cell selector: `0 = 4 us`, `1 = 2 us`, and documents mode `$0F` for the 3.5-inch/fast setting.

P0.2C7 therefore changes one host-side variable only:

1. Keep FujiNet P0.2C4 firmware unchanged.
2. After the normal SmartPort arm call returns, preserve the IIgs Speed register as in C5/C6.
3. Disable the IWM drive, read/save the current mode through Status, then write and verify mode `$0F` while DRIVE is disabled and Q6 is asserted.
4. Enable DRIVE and select Q7=0/Q6=0 Read Data.
5. Receive and validate the existing C4 marker plus deterministic 512-byte payload.
6. On success or timeout, reset the SmartPort bus, restore the previous IWM mode, and restore the exact IIgs Speed register.

Acceptance criterion: `FAST PASS: exact 512-byte 2us payload verified.`

If P0.2C7 still times out, the next diagnostic should capture IWM Status/Handshake/Data observations during the known C4 transmit window rather than changing FujiNet timing again.
