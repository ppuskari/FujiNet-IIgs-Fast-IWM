# P0.2C5 diagnosis

P0.2C4 hardware proved:

- exact READBLOCK `$7FA55A` decoded;
- delayed autosend scheduled;
- `FASTIWM C4 AUTO TX START` reached;
- no `AUTO TX DONE` followed.

Therefore the failure is inside `iwm_send_fast_probe_spi()`.

The private transmitter uses a second ESP-IDF SPI device handle (`spifast`) on the same host as the proven SmartPort transmitter. P0.2B/C4 disabled interrupts before calling `spi_device_polling_transmit(spifast, ...)`.

P0.2C5 acquires `spifast`'s bus with `spi_device_acquire_bus(spifast, portMAX_DELAY)` while interrupts/scheduler are still available, then disables interrupts only for the physical polling transmit and releases the bus afterward.

Expected serial split:

- `BUS ACQUIRE START` only: another transaction still owns the SPI bus.
- `BUS ACQUIRE DONE` but no `BUS RELEASE`: polling transmit itself hangs.
- `BUS RELEASE ret=0` + `AUTO TX DONE`: second-device bus arbitration was the blocker.

Host remains `FASTPROBE-P0.2C.po`.
