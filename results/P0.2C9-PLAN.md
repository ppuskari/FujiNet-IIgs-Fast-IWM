# P0.2C9 — paired host-ready 2 µs link

P0.2C8 fixed the 65816 immediate-width BRK, then exposed the next problem:
the host waited forever for an exact IWM mode `$0F` while FujiNet transmitted
on a fixed 50 ms timer. The observed live mode was `$0C`; its C bit is already
set, so the IWM is already using 2 µs cells, but its H/L bits did not accept
the attempted update.

P0.2C9 makes the link deterministic as a matched host/firmware pair:

1. Standard SmartPort `READBLOCK $7FA55A` arms one transfer at 4 µs.
2. FujiNet returns the normal dummy block and waits; no transmit timer runs.
3. The IIgs attempts the documented ROM-style `$0F` mode write for a bounded
   interval. Exact `$0F` is preferred, while any observed mode with C=`1`
   is accepted for this read-only polling experiment.
4. The IIgs establishes SmartPort phase state `1010`, selects DRIVE ON and
   Read Data, then raises PH0 to produce `1011` only when polling is live.
5. The FujiNet phase ISR latches that READY request. Normal service context
   acquires the proven 2 MHz SPI device and sends one deterministic packet.
6. The IIgs validates all 512 bytes, resets the bus, and restores the saved
   IWM mode and Speed register.

This uses the native IWM C bit for 2 µs cell timing without setting IIgs
`$C031` 35DISK routing, because the target is physically a SmartPort FujiNet
rather than a 3.5-inch dumb drive.
