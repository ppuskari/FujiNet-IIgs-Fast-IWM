# FASTIWM P0.2C17 plan

P0.2C16 reproduced the C15 crash exactly at `$0A/0781` with a `BRK B0`.
Mapping that address into the built OMF executable identified the bytes
`C9 08 00 B0`: Merlin assembled `cmp #FastReadySampleLimit` with a 16-bit
immediate, although the processor reaches the instruction with the accumulator
in 8-bit mode. The IIgs therefore executes `C9 08`, then interprets the surplus
`00 B0` as the observed `BRK B0`.

P0.2C17 explicitly sets Merlin's entry state to `MX %10` before the first
immediate instruction in `FastByteReadyC`. The isolated host builder also
checks the listing and requires that compare to encode as exactly `C9 08`, so a
future width regression fails the build instead of producing a crashing disk.

The remainder of the host trace is unchanged. P0.2C17 is paired with the
already-flashed P0.2C14 firmware; no FujiNet reflash is required.
