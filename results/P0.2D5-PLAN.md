# P0.2D5 safe SmartPort return

The D4 run proved 914 logged 16 KiB batches and at least 14.97 MiB of clean
2 us transport without a FujiNet packet error or DOC underrun. The eventual
IIgs monitor stop was in the copied bank-zero SmartPort thunk:

```text
00/194B: 00 F0  BRK F0
P ... m=1 x=1
```

With the observed thunk base `$1900`, `$194B` is the high byte of the
assembled `AND #$00FF` in the return path. The old sequence restored caller P
before that instruction. If caller M was 8-bit, the processor consumed only
the `$FF` byte and executed the remaining `$00` as BRK.

P0.2D5 keeps M/X 16-bit through `TYA` / `AND #$00FF`, branches on the complete
result, then restores caller P immediately before setting carry and returning
with `RTL`. It changes only the IIgs host. Keep the proven P0.2D4 FujiNet
firmware flashed.

The next hardware test should use the startup order proven by D4: start the
provider with no station selected, launch the D5 client, then tune from the
provider web UI. Let playback cross the prior 12-minute failure window.
