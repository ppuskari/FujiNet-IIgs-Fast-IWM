# FASTIWM P0.2C15 plan

P0.2C14 proved the physical route controls are coherent while the private
packet is transmitted:

```
phase=0b en35=0 d1=0 d2=1 hdsel=0
```

Together with host mode `$0F` and `DISKREG $40`, this completes the 0.5 us
versus 1 us pulse-width comparison under the intended 3.5-inch route. Both
shapes still time out at the marker scan.

P0.2C15 is a host-only observability build paired with the already-flashed
P0.2C14 firmware. It keeps the C14 route, mode, READY edge, and 0.5 us
waveform unchanged. During the receive loop it records at most the first
eight values for which IWM Read Data presents bit 7. It performs no TextTools
or screen I/O until after the disk interface is reset.

The timeout report adds:

```
IWM ready samples=$0000 data=0000 0000 0000 0000 0000 0000 0000 0000
```

- A count of zero isolates the failure below byte framing: no complete byte
  ever reaches the IWM latch.
- A nonzero count identifies the actual received byte values and separates a
  framing/polarity problem from the marker scanner.
- A successful full payload remains the primary acceptance criterion.
