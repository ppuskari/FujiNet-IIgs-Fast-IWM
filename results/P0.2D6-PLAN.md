# P0.2D6 direct Tool225 ring decode

D5 removed the bank-zero thunk's 8-bit immediate failure. Its next long run
reached 15,040,512 provider bytes (918 complete 16 KiB batches) before the
monitor stopped at `$0A/F401` with `D=$0800`, `S=$1F78`, and `B=$7E`.

Unlike the D4 `$00/194B` failure, this state is inside a toolbox routine with
the data bank set to the current 512 KiB ring destination. The D1 path was
calling Memory Manager `_BlockMove` once for every 512-byte packet while
Tool225 interrupts were live—more than 29,000 calls before this failure.

P0.2D6 removes Memory Manager entry from the live playback path:

- the 8-to-7 decoder stores all 512 reconstructed bytes directly into the
  current 24-bit circular-ring destination;
- the final decoded byte uses the same direct destination;
- the 32-byte provider status reply uses a bounded internal copy loop.

Initialization and pre-playback copies remain unchanged. FujiNet P0.2D4 is
unchanged and stays flashed. The next run should cross both the prior 15 MiB
and 15-minute boundaries; a 30-minute run is the first useful soak target.
