# P0.2D2 reset-free provider batches

P0.2D1 proved the TCP provider, PSRAM FIFO, 32-packet 2us batches, exact
512-byte PCM decode, and 512 KiB Tool225 ring. Field logs also showed that
every successful batch called `ResetFastBusC`, presented SmartPort reset
phase `0101`, and forced complete device re-enumeration. A later arm raced
that enumeration, produced repeated `Send REQ timeout`, and stopped after
`FASTIWM TX START packet=0` before the 480 KiB DOC start threshold.

P0.2D2 changes only the batch boundary and recovery containment:

- A successful 32-packet batch restores the saved IWM mode and IIgs speed
  while retaining the normal upstream SmartPort phase state `1010`.
- Phase `0101` remains reserved for timeout, corrupt data, DOC failure,
  underrun, or an explicit mid-batch user stop.
- A new FujiNet provider session clears all pending fast-request state and
  per-session counters.
- Fast-SPI bus acquisition is bounded at 100 ms so a collision reports a
  transport error instead of waiting forever.
- TCP provider pacing, the 64 KiB PSRAM FIFO, 16 KiB batches, the 480 KiB
  DOC prefill, 512 KiB Tool225 ring, and 21973-byte/sec drain are unchanged.

Expected serial behavior: consecutive `D2 PROVIDER BATCH DONE` lines with
no `Reset`/INIT enumeration between them. After 30 batches the IIgs starts
DOC playback with 480 KiB prefilled; the provider continues near its existing
175.8 kbit/sec target and short rate variation is absorbed by the ring.
