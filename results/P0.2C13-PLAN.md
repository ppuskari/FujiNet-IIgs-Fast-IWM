# P0.2C13 — documented IIgs 3.5-inch route

C12 proved that the host reached exact IWM mode `$0F` and that FujiNet
completed the 2 MHz, 1-us-pulse private transmission. It still returned no
IWM byte.

The remaining host routing bug is in P0.2C11: bit 6 of `$C02D` must be clear
to force internal Slot 6, but bit 6 of `$C031` must be **set** to select the
IIgs 3.5-inch path. C11/C12 cleared both bits and therefore listened on the
5.25-inch path while FujiNet drove the 3.5/SmartPort Read Data line.

P0.2C13 changes only the host route:

1. Preserve `$E1C02D` and `$E1C031`.
2. Clear `$E1C02D` bit 6 for internal Slot 6.
3. Set `$E1C031` bit 6 for the documented 3.5-inch path.
4. Require exact IWM mode `$0F`.
5. Use the existing 1010-to-1011 READY edge with the already-flashed P0.2C12
   FujiNet transmitter.
6. Restore both IIgs registers and the original IWM mode on exit.

On timeout the host reports both saved/active IWM mode and DISKREG values.
