# FASTIWM P0.2C16 plan

P0.2C15 reached its new byte-ready trace path and then crashed at
`$0A/0781` with `Y=$FFDF`. That value is the live `ReadIWMByteC` countdown,
which proves the intended `TAY` did not execute. The trace changed the CPU
accumulator to 16-bit mode, but its source omitted the matching Merlin `MX`
annotation. Merlin therefore emitted the immediate operand at the old width;
the `TAY` opcode was consumed as operand data and the stale Y register caused
an out-of-range indexed trace store.

P0.2C16 corrects the transform by pairing both runtime width changes with
explicit assembler-state directives:

```
rep #$20
mx  %00
...
sep #$20
mx  %10
```

The host remains otherwise identical to C15/C14 and is paired with the
already-flashed P0.2C14 firmware. A nonzero byte sample count is expected
because C15 could only enter the faulty path after observing Read Data bit 7.
