# P0.2D1 — FujiNet TCP-provider DOC streamer

P0.2D1 turns the proven P0.2D0 2-us PCM experiment into a continuous client
for the existing `22-mono` raw-U8 provider on TCP port 22510.

## Matched data path

1. FujiNet connects to `[Network] netstream_host` and `netstream_port`
   (port 22510 is used when the configured port is zero).
2. After Wi-Fi startup, FujiNet lazily allocates a 64 KiB FIFO in PSRAM (four
   complete transfer batches); the IIgs owns the 512 KiB playback reservoir.
3. The IIgs polls a normal 4-us status block until a complete 16 KiB batch is
   resident, then arms 32 fast packets.
4. Each 586-byte IWM-safe packet decodes to exactly 512 PCM bytes: 73 groups
   carry 511 bytes and a two-byte tail carries byte 512.
5. The IIgs writes the decoded data into the locked 512 KiB Tool225 ring.
6. Tool225 starts after 30 batches / 480 KiB, exactly matching the proven
   Uthernet II provider profile. The ring wraps after 1024 packets.
7. Provider waits and TCP reconnect work occur between batches with IIgs
   interrupts enabled. The fast path never waits on the network while DOC
   interrupts are masked.

## Controls and pass criteria

- Press any key while streaming to stop cleanly.
- The host fails on provider/configuration error, fast-batch timeout, Tool225
  error, or if Tool225's monotonic source counter catches the producer.
- A clean stop reports `underrun=$0000` and the measured provider PCM rate.

## Provider configuration

Run the existing `22-mono` provider, then configure FujiNet's Network Stream
host to the provider machine and port to `22510` in the FujiNet web UI (or in
`fnconfig.ini` as `netstream_host=` and `netstream_port=22510`).
