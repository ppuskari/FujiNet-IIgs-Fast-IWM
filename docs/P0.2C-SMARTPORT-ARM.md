# P0.2C — SmartPort-armed Fast-IWM wire test

P0.2B5 proved FujiNet receives ordinary SmartPort traffic while the experimental raw phase states `1110` / `1111` never appeared in the diagnostic log. Upstream FujiNet treats `1010` and `1011` as the actual SmartPort enable states.

P0.2C removes the private `1110/1111` trigger.

1. The IIgs uses the hardware-proven direct standard SmartPort `READBLOCK $01` path from SPBENCH P0.1B3.
2. It requests reserved block `$7FA55A`.
3. Experimental FujiNet firmware intercepts that block before media I/O, arms Fast-IWM, and returns a normal 512-byte 4-us dummy block so the ROM call completes normally.
4. The IIgs then directly establishes normal SmartPort enable state `1010` and raises PH0 to form `1011`.
5. When armed, FujiNet intercepts `1011` before normal command-packet receive and queues one private Fast-IWM packet.
6. `systemBus::service()` performs the 2-MHz SPI transmit outside the GPIO ISR.
7. The IIgs receives through the IWM read-data register and validates the deterministic 512-byte payload.

Normal SmartPort remains 1 MHz / 4 us. Production Rev1 runtime detection remains unchanged. `REV1DETECT`, `MASTERIES_*`, and `NO3STATE` stay disabled. A SmartPort reset clears an outstanding arm/request. Serial diagnostics report ARM, REQ, TX START, and TX DONE.
